# Лабораторная работа №3 — транскрипция аудио и поиск ключевых слов

Версия: 1.0.0

## 1. Цель работы

Разработать REST API для автоматического распознавания русской речи из аудиофайлов и поиска ключевых слов в распознанном тексте. Реализовать проверку входных данных, возврат временных сегментов и результатов обработки в JSON. Развернуть приложение в Docker и проверить его работу на реальной аудиозаписи.

Вариант задания: 20 — Туризм.

## 2. Используемые технологии

- Python 3.10
- FastAPI для реализации REST API
- Uvicorn в качестве ASGI-сервера
- faster-whisper для распознавания речи
- Whisper base в качестве модели распознавания
- PyYAML для чтения конфигурации сценария
- pytest и httpx для автоматического тестирования
- Docker для контейнеризации приложения
- Docker Compose для запуска и управления контейнером
- Swagger UI для интерактивной проверки API

## 3. Сценарий и ключевые слова

Реализован сценарий `tourism` — туризм.

Список ключевых слов хранится в файле `config/keywords.yaml`.

Используемые ключевые слова:

- `отель`
- `билет`
- `тур`
- `экскурсия`

Поиск выполняется в распознанном тексте без учёта регистра. Для поиска используются отдельные словоформы, заданные в конфигурации.

## 5. Установка и запуск

### Требования

- Linux или другая совместимая с Docker операционная система.
- Python 3.10 для локального запуска.
- Docker Engine и Docker Compose v2 для контейнерного запуска.
- Доступ к сети при первоначальной загрузке модели Whisper.

### Установка зависимостей для локального запуска

Создать виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Если виртуальное окружение уже создано, повторно создавать его не нужно.

### Локальный запуск

Из корня проекта выполнить:

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

После запуска API доступен по адресу:

```text
http://127.0.0.1:8000
```

Интерактивная документация Swagger UI:

```text
http://127.0.0.1:8000/docs
```

## 6. Запуск в Docker

### Сборка и запуск

Для сборки образа и запуска контейнера выполнить:

```bash
sudo docker compose up --build -d
```

В проекте используются:

- Образ приложения `sii-lr03-api`.
- Контейнер `sii-lr03-api`.
- Порт `8000` для доступа к API.
- Именованный том `whisper_models` для хранения загруженной модели.
- Политика перезапуска `unless-stopped`.

### Проверка состояния контейнера

```bash
sudo docker compose ps
```

### Просмотр журналов

```bash
sudo docker compose logs --tail=100 api
```

### Перезапуск приложения

```bash
sudo docker compose restart api
```

### Остановка приложения

```bash
sudo docker compose down
```

При остановке через `docker compose down` именованный том с моделью по умолчанию сохраняется.

## 7. API

### GET /health

Проверяет состояние приложения и готовность модели.

Пример ответа:

```json
{
  "status": "ok",
  "model_loaded": true,
  "scenario_id": "tourism"
}
```

### POST /transcribe

Принимает аудиофайл через `multipart/form-data`.

Обязательное поле запроса:

- `file` — аудиофайл.

Входной файл проверяется на допустимость формата, размер и продолжительность. Максимальный размер файла — 20 МБ, максимальная продолжительность — 60 секунд.

Ответ содержит следующие поля:

- `scenario_id` — идентификатор сценария.
- `scenario_name` — название сценария.
- `text` — распознанный текст.
- `language` — язык распознавания.
- `segments` — временные сегменты распознанной речи.
- `keywords_found` — найденные ключевые слова и количество совпадений.
- `model` — идентификатор используемой модели.
- `model_version` — версия API модели.
- `latency_ms` — время обработки в миллисекундах.

## 8. Тестирование

Автоматические тесты запускаются локально:

```bash
source .venv/bin/activate
pytest -v
```

Проверяются следующие сценарии:

- Успешная проверка состояния API.
- Успешная обработка запроса на транскрипцию с тестовым распознавателем.
- Обработка пустого файла.
- Отклонение неподдерживаемого формата.
- Отклонение аудио, превышающего допустимую продолжительность.

Результат выполненного тестирования:

```text
5 passed in 0.75s
```

Тесты используют подменённый распознаватель для проверки API и не заменяют проверку реальной модели на аудиозаписи.

## 9. Проверка на реальной аудиозаписи

Для практической проверки использовалась собственная русскоязычная аудиозапись `samples/tourism.wav`.

Запрос к API:

```bash
curl -X POST \
  -F "file=@samples/tourism.wav" \
  http://127.0.0.1:8000/transcribe
```

В результате приложение распознало речь о бронировании отеля, покупке билета и экскурсии по историческим местам.

### Найденные ключевые слова

| Ключевое слово | Количество |
|---|---:|
| отель | 1 |
| билет | 1 |
| тур | 1 |
| экскурсия | 1 |

Все четыре ключевых слова туристического сценария были обнаружены.

### Результаты обработки

- Модель: `whisper-base`.
- Язык распознавания: `ru`.
- Количество временных сегментов: 2.
- Время обработки: приблизительно 4,3–4,7 секунды на используемом сервере.
- Результат возвращён в формате JSON.

В распознанном тексте присутствовали отдельные ошибки распознавания слов. Это демонстрирует, что результат автоматической транскрипции может требовать дополнительной проверки.

## 11. Ограничения

- Автоматическое распознавание речи может содержать ошибки.
- Качество результата зависит от качества записи, шума и произношения.
- Поиск выполняется по заданным словоформам, а не по всем возможным формам слова.
- Производительность зависит от ресурсов сервера и параметров модели.
- При первом запуске необходим доступ к сети для загрузки модели.
- Доступ к API в локальной сети не означает, что он доступен из интернета.

Полученные результаты подтверждают работоспособность распознавания речи, поиска ключевых слов и REST API в контейнерной среде.
